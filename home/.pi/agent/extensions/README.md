# Pi extensions

Tracked first-pass Pi extensions for this dotfiles setup.

- `permission-gate.ts`: ask/block bash commands matching `permissionGate.bash` patterns; its `rmPolicy` allows removal in Git repositories and temporary directories, blocks direct removal of home or `/`, blocks recursive removal elsewhere, and asks for non-recursive removal elsewhere
- `protected-paths.ts`: block writes to secret or generated paths
- `status-line.ts`: show simple turn progress in the footer
- `model-status.ts`: notify when the active model changes
- `pr-watch.ts`: session-local multi-PR watcher that wakes after PR, `gh stack`, and git push activity, batches CI and feedback updates until the agent settles, supports paused delivery while polling continues, shares worker watch membership with parent orchestration sessions, and reports settled workers that have no watched PR. Associated workers discover their branch PR on startup, settlement, and polling even when no supported shell command enrolled it. Outside an orchestration, SHA watch covers a feature branch with no watched PR and, once, the merge commit of a watched PR you authored or the exact commit pushed directly to the default branch. Fixed-commit watches survive reloads and wait for chained post-deploy workflows; they never follow the default branch tip and ignore scheduled and manually dispatched runs. SHA completion history survives temporarily missing workflow runs and session reloads, while new workflows and rerun attempts still notify. In an orchestration, automatic enrollment watches only the PRs its workers publish (viewing any other PR does not enroll it) and, once, the merge commit of its most recently merged worker PR; it never follows its landing branch tip. The orchestrator receives passing CI and PR feedback, the worker receives failing CI, merge conflicts, and orchestrator messages from `~/.agents/skills/orchestrator/scripts/message-worker`, and Codex reviews are ignored
  - Pi-only tools `watch_pr({ pr: "104" })` and `unwatch_pr({ pr: "https://github.com/owner/repo/pull/104" })` explicitly opt a PR in or out for regular sessions, workers, and orchestrators. Numbers refer to the current repository; URLs work across repositories. Overrides survive reloads and take precedence over command discovery, worker branch discovery, and worker snapshots. Opt-in requires an open PR and resumes watching; opt-out also clears that PR's buffered updates and merge-commit watch, even when it is not currently enrolled. Other PRs and independent branch SHA watches remain in place. Worker opt-ins publish membership to their parent; parent opt-outs are local to the parent. CI/feedback routing and filtering remain unchanged. `/pr-watch add/remove` use the same overrides; `/pr-watch reset` clears them.
- `slack-watch.ts`: session-local Slack watcher. The Pi tools `watch_slack({ target, thread_ts?, from?, since?, note? })` and `unwatch_slack({ target, thread_ts? })` take a Slack URL or a channel/DM ID: a channel or DM watch covers top-level messages, and a thread watch (a message link, or a channel ID plus `thread_ts`) covers its replies. It polls `slackcli` every 20s, skips your own messages and agent progress updates (messages with only `plan` blocks), batches new messages while the agent is busy, and delivers them as `<slack-watch-harness-notification>` turns once it settles, listing any buttons with their `action_id` and `value`. Watches survive reloads and catch up on messages posted while the session was closed. `/slack-watch [list|poll|clear]`.
- `provider-reliability/`: guard streaming Anthropic requests against server-side stalls by withholding the response until the first real SSE event and transparently re-sending when none arrives within 25s, or within 3s of headers (`PI_STALL_FIRST_EVENT_DEADLINE_MS`, `PI_STALL_POST_HEADERS_GRACE_MS`, `PI_STALL_MAX_RESENDS`; a deadline of 0 disables it); also log Anthropic-only per-request timing (headers, first event, end, request ID), stalls, and re-sends to `~/.pi/agent/logs/provider-requests.jsonl`, without footer status messages; other providers (including OpenAI Codex WebSockets) pass through untouched
- `orchestrator.ts`: append the canonical `~/.agents/skills/orchestrator/SKILL.md` instructions to the system prompt before each agent run when `PI_ORCHESTRATION_SESSION_ID` is set; role instructions stay outside compacted conversation history, and PR Watch restores the variable on resume. Workers with only `PI_PARENT_ORCHESTRATION_SESSION_ID` keep their ordinary role. Use `/reload` to load this extension in an existing session.
- `trust-all.ts`: automatically trust every project to bypass project trust prompts
- `collapsed-bash-calls.ts`: show only the first 3 lines of a multi-line bash command until the tool row is expanded (`ctrl+o`); HTML exports render rows collapsed, so they show the preview too
- `visible-markdown-links.ts`: keep assistant Markdown links clickable and print each hidden external URL after its label
- `plan-mode/`: read-only planning mode with extracted steps and execution tracking
- `otel-tracing/`: export session, prompt, LLM, and tool traces over OpenTelemetry
